# Module 22 · Career Ready

**Time:** ~15 hours · **Prerequisites:** none for 22.4–22.5 (read them when you start the capstone); the rest after the capstone

## Why this module matters
The course's goal is a job, not just a finished game. This module covers what nobody teaches at university: how work actually happens in a real codebase, how pull requests and reviews work, how to use AI tools professionally, how to present your work so it gets noticed, and how to prepare for interviews. It also includes a mock interview format you can practise with again and again.

## Learning objectives
By the end of this module you can:
- find your way around an unfamiliar codebase, ask good questions and ship small changes
- write pull requests that are easy to review, and review others' code kindly and usefully
- use AI tools at work responsibly, within company policies, while keeping your skills sharp
- present your capstone as a portfolio case study, with a strong README, GitHub profile and CV
- prepare for each interview stage, and practise with a structured mock interview
- choose what to learn next

## Checkpoint quiz
1. How long should you struggle before asking a question at work, and what goes in a good question?
2. What sections make a good pull request description?
3. What must you check before using an AI tool on a company codebase?
4. What are the most important sections of a portfolio case study?
5. What's the formula for a strong CV bullet?
6. What's the biggest mistake candidates make in live coding?
7. Describe the STAR method.
8. In the mock interview format, which six areas does the rubric score?

<details><summary>Answers</summary>

1. About 15–30 minutes. Include context, the goal, what you tried, expected versus actual behaviour, and a specific ask.
2. What, why, how, how to test, screenshots for UI changes, and notes on open questions.
3. Which tools are approved, what data may be shared, any licensing rules, and whether the team expects disclosure.
4. The problem, the architecture and, most of all, the hardest problem and how you solved it, followed by other decisions, quality evidence and what you'd do next.
5. What you built + how (the technologies) + the result or why it matters.
6. Silence: not thinking out loud.
7. Situation, Task, Action (the longest part: what *you* did), Result (including what you learned).
8. Communication, problem solving, code quality, fundamentals, testing mindset and project knowledge.
</details>

## Extra practice
1. **Three mock interviews** using the format in 22.5: with a friend, a mentor or an AI assistant. Score each one, and track your rubric scores over time.
2. **A first open-source PR**: a docs fix or a small bug in a project you use (22.2).
3. **Write one blog post** about the hardest problem in your capstone. Link it from your CV and your case study.
4. **Apply for five jobs**, then tick the last box in `PROGRESS.md`.
